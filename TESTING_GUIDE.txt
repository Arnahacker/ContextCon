=====================================================================
  INVARIANT - STEP-BY-STEP TESTING GUIDE (Windows / PowerShell)
=====================================================================

WHAT YOU ARE TESTING
--------------------
INVARIANT is an underwriting desk. You type a request about a company
(any wording, any language), and it:
  1. READS it   - an AI (Gemini) fills in a form: company, city, staff, units...
  2. CHECKS it  - looks the company up in Crustdata (headcount, offices, jobs, news)
  3. DECIDES    - fixed rules (not the AI) give QUOTE / REFER / DECLINE / HOLD
The big claim: the SAME request worded differently gets the SAME answer,
and every reason links to a source.

TWO WAYS TO RUN IT  (read this first - it matters)
--------------------------------------------------
 A) DEMO MODE (offline)  - uses saved sample data. Free. No keys used.
    The built-in example companies (Kanpur Hide Exports, Agra Footwear
    Works, etc.) are MADE UP and only exist in this saved data.
    -> Use this for Parts 1-5. Everything should work perfectly.

 B) LIVE MODE  - uses your real Crustdata + Gemini keys (from the .env file).
    Costs a little Crustdata credit per case.
    -> Use this for Part 6, with REAL company names.
    -> In live mode the made-up example companies will just say
       "HOLD - ambiguous company" because they do not exist. That is
       correct behaviour, not a bug.


=====================================================================
PART 0 - START THE APP IN DEMO MODE
=====================================================================
1. In VS Code, click into the terminal where the server is running.
2. Press  Ctrl + C  to stop it. (You get the "PS C:\...>" prompt back.)
3. Type these three lines, pressing Enter after each:

     $env:PYTHONUTF8 = "1"
     $env:INVARIANT_OFFLINE = "1"
     .venv\Scripts\python -m uvicorn invariant.api.app:app --port 8000

4. Wait until you see:   Uvicorn running on http://127.0.0.1:8000
5. In your browser, open (or refresh):   http://127.0.0.1:8000

   Leave this terminal open. Every click you make in the browser shows
   up there as a line like  "POST /api/cases HTTP/1.1" 200 OK
   That is how you "see it running".

WHAT THE SCREEN LOOKS LIKE
  - Top bar: "INVARIANT", three tabs: Underwrite | Invariance | Tests,
    and a "credits" counter on the right (Crustdata credits spent).
  - Underwrite tab: a text box, a blue "Underwrite" button, and example
    buttons: Hero, Clean, Hidden hazard, Bad news, Lookalike, Injection.


=====================================================================
PART 1 - THE UNDERWRITE TAB (one scenario at a time)
=====================================================================
For each test below: click the example button (it fills the text box),
then click the blue "Underwrite" button, then compare with "EXPECT".

After clicking Underwrite you get these boxes:
  - Company           : which company it matched + "Prompt read by ..."
  - Gap table         : what the broker declared vs what public data says
  - Why: rules applied: each rule that changed the price, and its sources
  - Decision          : QUOTE / REFER / DECLINE / HOLD + premium in Rs
  - Ask the broker    : follow-up questions with answer buttons
  - What would change my mind : "If X -> QUOTE" + a "Flip it" button
  - Findings          : special notes (e.g. injection attempt, API failure)

---------------------------------------------------------------
TEST 1.1  "Hero"  (the main demo - a company hiding things)
---------------------------------------------------------------
 Click: Hero -> Underwrite
 EXPECT (first result):
   - Company: Kanpur Hide Exports Pvt Ltd, "Prompt read by saved LLM reading"
   - Decision: HOLD, "awaiting answers: need 2 answer(s) to price
     (cover_type, sum_insured)"  -> the broker never said what cover or
     how much, so it refuses to guess a price.
   - Gap table shows the lies:
       headcount: declared 120  vs record 310   (contradicts)
       sites:     declared 3    vs record 4     (contradicts)
       undeclared sites: Unnao, Kanpur Dehat, Chennai
       hazardous activity: tannery / tanning (from their job posts)
   - Ask the broker: cover_type (buttons fire / wc / fire_wc),
     sum_insured (text box), claims_history (yes / no)

 NOW ANSWER THE BROKER QUESTIONS:
   a) cover_type: click  fire_wc
   b) sum_insured: type  5 crore   (any wording works: "50000000",
      "5 cr", "five crore") and click Send
   c) If a "Yes / Edit" confirmation appears for what it understood,
      click Yes.
 EXPECT after answering:
   - Decision changes to REFER, premium about Rs 60.9 lakh
     (range about Rs 49.1 lakh - Rs 72.8 lakh)
   - Why: rules applied lists HEADCOUNT_UNDERSTATED, UNDECLARED_SITE (x3),
     UNDECLARED_HAZARD

 CLICK AROUND:
   - Click any number/value in the Gap table or "Because" column.
     A side panel opens showing the SOURCE of that fact (which API,
     the exact quote). Every fact must have one. Click Close.
   - In "What would change my mind", click "Flip it" on any line.
     The panel shows what the decision WOULD be if that one fact were
     different. Nothing is saved - it's a what-if.
   - claims_history: try clicking "Don't know" - it should still decide,
     just noting the claims history is unknown.

=====================================================================
PART 5 - LOOK UNDER THE HOOD (how it is running)
=====================================================================
 With the server running, open these in your browser:

   http://127.0.0.1:8000/docs
       Interactive API page (auto-generated). Every endpoint is listed.
       Click one -> "Try it out" -> "Execute" to call it directly.
       Try POST /api/cases with:  {"prompt": "Agra Footwear Works wants fire cover for 3 crore. 85 staff, one factory in Agra."}

   http://127.0.0.1:8000/api/cases
       Raw list of every case you've run (saved in data\cases.sqlite).

   http://127.0.0.1:8000/api/meter
       Crustdata usage: calls made, how many came from cache, credits spent.

 In the server terminal, every request shows as a log line. In live mode
 a slow request (several seconds) means it's calling Gemini / Crustdata.

 Where things are saved:  the  data\  folder in the project
   - cases.sqlite  = case history
   - cache files   = every external API answer, so the same request
                     never costs credits twice


=====================================================================
PART 6 - LIVE MODE (real companies, real APIs)
=====================================================================
 1. In the server terminal press Ctrl + C.
 2. Type (the second line switches demo mode OFF):

     $env:PYTHONUTF8 = "1"
     Remove-Item Env:INVARIANT_OFFLINE -ErrorAction SilentlyContinue
     .venv\Scripts\python -m uvicorn invariant.api.app:app --port 8000

    (Or just open a brand-new terminal and run only the 1st and 3rd lines.)
 3. Refresh http://127.0.0.1:8000

 4. Type a request about a REAL Indian company, for example:
      Super Tannery Ltd, leather company in Kanpur, says 300 employees, 2 units. Fire cover 10 crore.
      Relaxo Footwears, Delhi, footwear manufacturer, 500 staff, fire cover 20 crore.
      Page Industries, Bengaluru, garment maker, 1000 employees, 5 units, fire cover 50 crore.
    Click Underwrite. It takes longer (a few seconds to ~30s).

 EXPECT:
   - Company box: "Prompt read by Gemini"  (proves your Gemini key works)
   - The credits counter (top right) goes up a little (proves Crustdata works)
   - A real company match + crustdata id, OR "HOLD - ambiguous company" with
     candidates to pick from if the name matches several companies.
     Picking the right one is normal and expected.
   - Gap table with REAL numbers from Crustdata. Results depend entirely on
     what Crustdata knows about that company - small firms may have little
     data, which shows up as "unconfirmed" or "unavailable".
   - Any failed lookup gives HOLD "evidence unavailable" - by design it
     never pretends a missing answer means "all clear".

 TRY THE INVARIANCE CLAIM LIVE:
   Run the same real company twice with very different wording (polite
   English, then short Hinglish with typos). The second run should say
   "Same request as case ..." and give the same decision.

 IMPORTANT IN LIVE MODE:
   - Don't use the example buttons or the Invariance / Tests tabs - their
     companies are made up, so they'll HOLD / fail, and each run costs
     credits. Use demo mode (Part 0) for those.
   - Re-running the exact same request is free (it's cached).
   - Middle ground to save credits: Gemini live but Crustdata from saved data:
       $env:INVARIANT_EVIDENCE_OFFLINE = "1"   (before starting the server)

 Paste (live mode):

 If asked which company, pick Bata India Limited (bata.in).

 7.1 Answer: claims history = no, cover = fire_wc.
     EXPECT: HOLD, one question left: the total sum insured.
 7.2 Sum insured: click "Don't know".
     EXPECT: only ONE new question: "Is the building owned or rented?"
     Machinery and stock are already estimated from Crustdata's headcount
     (5,987) - see "(estimate)" rows in the gap table; click one to see the

 7.3a Click "rented".
     EXPECT: priced right away (REFER - Bata's headcount/sites don't match).
     Building = Rs 0. No area/roof question (useless once rented).
     Optional questions remain, each with a rupee value (wages, monthly sales...).
 7.3b (new case) Instead click "Don't know" on owned/rented.
     EXPECT: still priced, with rule UNDISCLOSED_ESSENTIAL x1.25 (penalty for
     withholding information only the applicant has). The top question is the
     sum-insured band. Pick "25+ Cr": the penalty disappears, and Findings
     flags "underinsurance" (25-100 Cr is far below what a 5,987-person
     company's machinery + stock suggests).
 7.4 Every rupee estimate is labelled "(estimate)" and uses illustrative
     norms (placeholders, not sourced figures), like the rate card.

 The rule now: a question that blocks pricing is ALWAYS shown; optional
 questions stop after 5 answers or when worth under Rs 5,000.


=====================================================================
TROUBLESHOOTING
=====================================================================
 "PYTHONUTF8=1 is not recognized"
     You used the Git Bash command in PowerShell. Use  $env:PYTHONUTF8 = "1"
     on its own line instead.

 "[Errno 10048] ... only one usage of each socket address"
     Something is already running on port 8000 (another terminal?).
     Stop it with Ctrl + C there, or use  --port 8001  and open
     http://127.0.0.1:8001

 Page doesn't load / "can't reach"
     The server isn't running - check the terminal for the
     "Uvicorn running on ..." line.

 "Could not read this prompt" (error 422)
     The reader couldn't pull a company out of the text. Name the company
     clearly, e.g. "XYZ Pvt Ltd, Kanpur, 100 employees".

 Everything says "ambiguous company" in live mode
     You're using the made-up demo companies. Use real company names, or
     switch to demo mode.

 Starting fresh in a new terminal: you ALWAYS need  $env:PYTHONUTF8 = "1"
 first ($env: settings only last for that terminal window).
